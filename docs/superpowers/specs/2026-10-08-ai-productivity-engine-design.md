# AI生产力引擎互动数据叙事设计

## 1. 项目目标

本项目是面向可视化导论课程评审的单页互动数据叙事作品，不是人工智能知识介绍站，也不是传统数据大屏。

作品需要用可验证数据、连续叙事和有意义的交互回答一个核心问题：

> 一次智能决策如何被嵌入生产流程，扩散为组织与产业变化，并最终转化为可持续的新质生产力？

作品应同时做到：

- 讲清楚从生产要素到生产结果的因果链；
- 通过真实案例区分节约型、增效型和创造型生产力；
- 让用户通过模拟器验证“AI投入不等于生产力提升”；
- 展示就业、能源、数据与算法风险，避免单向技术乐观主义；
- 形成适合课堂展示和五分钟讲解视频的视觉记忆点。

## 2. 核心观点

AI首先降低识别、预测、生成和决策的成本。当这些低成本决策被大量嵌入生产流程，流程和组织才会发生改变。只有当数据、流程、人员与治理共同适配时，AI能力才能转化为可持续生产力。

完整因果链为：

```text
数据 + 算力 + 算法
        ↓
识别 + 预测 + 生成 + 决策
        ↓
智能判断进入研发、生产、管理与服务流程
        ↓
等待、返工、资源配置和创新搜索方式改变
        ↓
成本、周期、质量和能力边界发生变化
        ↓
产业结构、岗位任务和社会代价发生变化
        ↓
治理决定这种生产力能否持续
```

## 3. 叙事主线

### 3.1 故事主角

全站的视觉主角是一个橙色“决策脉冲”。它代表一次AI判断，并在六幕叙事中持续存在：

- 开场：一次喷或不喷的判断；
- 要素汇聚：数据、算力和算法共同形成的AI能力；
- 流程重构：进入生产流程的控制信号；
- 产业扩散：在不同行业迁移的通用能力；
- 生产力实验室：用户可以调节的生产变量；
- 风险与结尾：必须由人类约束和负责的决策能力。

Three.js场景不是章节装饰，而是同一个对象随故事不断演化。

### 3.2 情绪曲线

```text
好奇：一次判断是怎么发生的？
惊讶：同类判断可以被规模化复制。
理解：规模化判断会改变生产流程。
兴奋：AI可以创造过去难以完成的新任务。
参与：如果由我配置企业，会发生什么？
质疑：增长的成本和风险由谁承担？
思考：我们希望AI替代人，还是扩展人？
```

## 4. 六幕内容结构

### 4.1 开场：喷，还是不喷

页面从一个具体决策开始。中央是一株植物的抽象点云，页面提出问题：

> 一株植物经过喷杆下方。系统必须在毫秒内判断：这是作物，还是杂草？

用户点击“做出判断”后，摄像头数据进入模型，橙色脉冲沿喷杆传播，仅激活对应喷嘴。镜头随后拉远，显示同类判断被大规模重复。

真实案例采用John Deere See & Spray。案例数据必须标记为厂商披露，不把商业宣传表述为独立研究结论。

本幕结论：

> 生产力的变化，开始于一次决策成本的下降。

### 4.2 要素汇聚：判断如何形成

镜头进入决策脉冲内部。数据、算力、算法三股粒子流进入同一核心，并依次形成识别、预测、生成和决策能力。

用户悬停任一要素时，其他粒子降低透明度，相关路径和解释变量被高亮。任一要素缺失时，系统展示对应失败状态：

- 数据不足：判断不稳定；
- 算力不足：无法进入实时流程；
- 算法不匹配：输入不能形成可靠行动。

本幕回答AI为何不只是一个普通软件工具。

### 4.3 流程重构：判断进入生产

固定视口中的横向流程依次展示研发、生产、管理和服务。垂直滚动控制流程推进。

用户可以切换：

```text
传统流程 → AI辅助流程 → 人机协同流程
```

切换时同时改变等待时间、返工路径、信息回流速度和人工复核节点。页面持续显示周期、成本、质量和创新范围四类结果，但所有数字必须来自真实数据或明确标注为教学模拟。

本幕结论：单次AI判断只有进入流程并改变资源配置方式，才会形成生产力。

### 4.4 产业扩散：三种生产力

案例不按行业平铺，而按生产力层次递进：

| 层次 | AI改变了什么 | 核心案例 | 叙事作用 |
| --- | --- | --- | --- |
| 节约型 | 减少完成同一任务所需投入 | See & Spray精准喷洒 | 降低材料与作业成本 |
| 增效型 | 缩短原有任务完成时间 | GitHub Copilot受控实验 | 改变任务分工与注意力配置 |
| 创造型 | 完成过去难以规模化完成的任务 | AlphaFold蛋白质结构预测 | 扩展科研能力边界 |

三个案例结束后，镜头拉远形成制造、医疗、农业、交通、教育和科研的行业星图。星图表达共享能力如何迁移，而不是制作装饰性的行业目录。

点击行业节点时，高亮该行业依赖的识别、预测、生成、决策和人工复核组合，并打开包含问题、介入位置、流程变化、结果和来源的案例面板。

### 4.5 生产力实验室：用户亲自验证

页面提出反问题：

> 既然案例有效，是不是投入越多AI越好？

用户调节以下参数：

- 企业规模；
- AI投入强度；
- 数据质量；
- 流程自动化率；
- 员工培训程度；
- 流程标准化水平；
- 治理投入。

联动输出包括产出指数、单位成本、交付周期、创新能力、转型摩擦和风险暴露。

模拟器至少能够形成三种可解释状态：

1. 技术孤岛：AI投入高，但数据和流程质量低；
2. 自动化陷阱：自动化率高，但培训和人工复核不足；
3. 人机协同：技术、流程、培训和治理相对平衡。

模拟器必须标记为“教学情景模型，不是企业预测”。公式、权重和假设可以展开查看。真实数据只用于确定合理基准区间，不能把模型输出伪装成统计事实。

### 4.6 增长的阴影与最终选择

生产力曲线上升后，页面暂停并提出：

> 如果计算没有消失，成本被转移到了哪里？

三维核心产生四条裂缝，分别对应：

- 就业与任务重构；
- 算力与能源消耗；
- 数据安全；
- 算法偏见与决策责任。

用户可以切换“无治理扩张”和“负责任采用”，观察培训、人工复核、能源效率和数据治理如何改变风险路径。

最终控制轴为“自动替代 ↔ 能力增强”：

- 只追求替代时，网络更简单、速度更快，但创新节点减少；
- 强调增强时，网络更复杂，需要培训和治理，但出现更多新任务；
- 完全拒绝AI时，风险较低，但效率和能力边界保持不变。

最终结论：

> AI不是天然的生产力。只有当它被嵌入合适的流程，被人正确使用，并受到有效治理时，智能能力才会转化为可持续的新质生产力。

## 5. 视觉系统

### 5.1 设计定位

这是一个全新建设的单页互动数据纪录片，面向课程评审，采用工业编辑式暗色视觉和实验性滚动叙事。

设计参数：

- `DESIGN_VARIANCE: 9/10`
- `MOTION_INTENSITY: 9/10`
- `VISUAL_DENSITY: 6/10`

### 5.2 色彩

- 主背景：`#080A0C`
- 次级表面：`#11161A`
- 主文字：`#ECEBE4`
- 次级文字：`#899197`
- 强调色：`#F26A2E`
- 网格与分隔：白色8%-14%透明度

橙色表示被激活的生产力。未经AI重构的对象保持灰色。页面不使用常见的紫蓝AI渐变，不使用彩虹行业配色。

### 5.3 字体与形态

- 中文标题：MiSans Heavy或思源黑体Heavy；
- 中文正文：MiSans Regular或思源黑体Regular；
- 数字与参数：IBM Plex Mono；
- 内容容器统一使用12px圆角；
- 参数控件可以使用胶囊形，但不把所有内容包装成玻璃卡片；
- 页面维持统一暗色主题，不在章节间切换亮暗模式。

### 5.4 导航

顶部使用不超过64px的固定导航：

```text
引擎 / 重构 / 产业 / 实验室 / 代价 / 结论
```

导航下方显示细线式章节进度。桌面端始终保持单行。移动端收起为当前章节和菜单按钮。

## 6. 动效与交互职责

### 6.1 Three.js场景

负责：

- 粒子汇聚；
- 决策核心形态变化；
- 产业关系网络；
- 镜头路径；
- 轻量选择性Bloom；
- 点击和悬停的三维拾取。

全站使用一个持续存在的Canvas，通过章节状态改变场景，不为每一幕重新创建WebGL上下文。

### 6.2 GSAP ScrollTrigger

负责：

- 章节钉扎；
- 滚动进度与镜头进度同步；
- 横向流程推进；
- 关键文本和图表进入时机；
- 三维场景状态之间的连续过渡。

不增加额外平滑滚动库，不监听原始`window.scroll`持续写入React状态。

### 6.3 D3与DOM

- `d3-force`计算行业关系网络初始布局；
- `d3-scale`完成真实数据到视觉尺寸的映射；
- SVG或Canvas负责精确二维图表；
- CSS负责按钮反馈、文字遮罩和普通悬停；
- React负责章节、案例和模拟参数状态。

同一元素不由多个动画系统同时控制。

## 7. 数据与案例规范

每一条数据记录包含：

```text
value / unit / year / geography / industry / methodology / sourceTitle / sourceUrl / sourceType
```

来源类型分为：

- 官方统计；
- 学术或研究报告；
- 企业披露；
- 教学情景模拟。

所有图表旁显示年份、单位和来源入口。页面提供统一的数据来源抽屉，并允许从图表直接定位相应条目。

首批案例来源：

- John Deere See & Spray：<https://www.deere.com/en-us/products-solutions/sprayers-and-applicators/see-spray-select>
- GitHub Copilot实验报告：<https://github.blog/wp-content/uploads/2023/06/Sea-Change-in-Software-Dev.pdf>
- Google DeepMind AlphaFold：<https://deepmind.google/science/alphafold/>
- IEA数据中心能源分析：<https://www.iea.org/news/data-centre-electricity-use-surged-in-2025-even-with-tightening-bottlenecks-driving-a-scramble-for-solutions>

实现前需要再次核对页面可访问性、发布日期、统计口径和原始报告。企业来源必须明确标记，不与独立统计混用。

## 8. 技术架构

项目保持为无后台的单页静态网站：

- Vite；
- React；
- TypeScript；
- Three.js；
- React Three Fiber；
- Drei；
- GSAP与ScrollTrigger；
- `d3-force`与`d3-scale`；
- 原生CSS变量与模块化样式；
- 本地JSON数据；
- GitHub Pages部署。

不增加路由、数据库、全局状态库、通用图表组件库或平滑滚动依赖，除非后续出现明确需求。

建议组件边界：

```text
AppShell
├── StoryNavigation
├── PersistentScene
│   ├── DecisionPulse
│   ├── FactorStreams
│   ├── ProcessEngine
│   ├── IndustryGalaxy
│   └── RiskFracture
├── StorySections
│   ├── OpeningDecision
│   ├── FactorChapter
│   ├── ProcessChapter
│   ├── IndustryChapter
│   ├── ProductivityLab
│   └── GovernanceChapter
├── DataSourceDrawer

```

三维组件只读取归一化章节进度和少量离散场景状态。连续帧值不进入React组件状态。

## 9. 性能与可访问性

### 9.1 性能等级

- 高性能桌面：约8,000-15,000个实例粒子，开启轻量Bloom；
- 普通设备：降低像素比、粒子数量和后期效果；
- 手机：约1,500-3,000个粒子，关闭景深和复杂后期；
- 低帧率设备：自动进入简化模式；
- 页面隐藏时暂停渲染；
- WebGL不可用时展示预渲染静态关键帧。

优先复用几何体和材质，粒子与重复节点使用实例化，动态分辨率上限默认不超过1.5 DPR。

### 9.2 可访问性

- 所有主要交互均可使用键盘；
- 三维可视化同时提供文本摘要；
- 图表不依赖颜色作为唯一编码；
- 正文与控件满足WCAG AA对比度；
- `prefers-reduced-motion`下取消镜头飞行、视差、持续旋转和滚动绑定；
- 焦点状态始终可见；
- 移动端不强制横向滚动劫持。

## 10. 错误与降级状态

- 数据文件加载失败：保留章节结构，显示可读错误和重新加载入口；
- 单条来源缺失：隐藏该数字，不用占位数字替代；
- Three.js初始化失败：切换到静态海报和SVG图表；
- 低性能模式：保留全部信息与交互，只减少粒子和后期特效；
- 模拟参数非法：在参数旁显示范围提示，不更新结果；
- 来源链接失效：在来源抽屉标记为待核验，不继续显示为已验证来源。

## 11. 响应式策略

- 桌面端使用固定Canvas、章节钉扎和横向流程；
- 平板端减少镜头位移，横向流程改为可控分段切换；
- 小于768px时取消复杂非对称布局，正文改为单栏；
- 行业星图在手机上改为可拖拽平面网络或列表与关系图组合；
- 模拟器在手机上先显示参数，再显示结果，提供固定“查看结果”入口；
- 所有章节使用`100dvh`相关布局，避免移动浏览器地址栏导致跳动。

## 12. 验收标准

### 12.1 叙事

- 用户能复述“一次判断如何成为生产力”的因果链；
- 三个案例分别支持节约、增效和创造三个层次；
- 风险章节与前文因果相连，不是附加伦理列表；
- 最终结论强调人、流程和治理，而不是技术决定论。

### 12.2 数据

- 页面中不存在无来源的精确数字；
- 企业披露、研究结论和教学模拟有明显区别；
- 每条来源都有年份、范围、单位和可访问链接；
- 模拟模型的公式与假设可见。

### 12.3 视觉与动效

- 全站使用一个持续演化的三维核心；
- 每项主要动效都能解释其叙事职责；
- 不使用AI紫渐变、装饰性粒子墙和重复三栏卡片；
- 页面暗色主题、强调色、圆角和字体系统一致；
- 减少动效模式仍能完整阅读和操作。

### 12.4 工程

- 桌面和手机均能完成全部核心路径；
- 低性能设备自动降级且不丢失信息；
- Three.js、GSAP和D3不重复控制同一元素；
- 构建通过，无控制台错误；
- GitHub Pages刷新和资源路径正常；
- Lighthouse性能、可访问性和最佳实践结果达到课程展示可接受水平。

## 13. 明确不做

- 不做多页面门户；
- 不做用户登录、后台或数据库；
- 不做无来源的实时数字大屏；
- 不把六个行业做成六张同构卡片；
- 不加入与叙事无关的小游戏；
- 不自动播放声音；
- 不为炫技加入全站自定义鼠标、双重滚动系统或持续故障特效；
- 不在第一版制作复杂三维工业城市和大量外部3D模型。

第一版的复杂度集中在一条完整故事、一个持续场景、三类真实案例、一个透明模拟器和一套可靠降级机制。
