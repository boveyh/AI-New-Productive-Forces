# AI生产力引擎互动数据叙事设计

## 1. 项目目标

本项目是面向可视化导论课程评审的单页互动数据叙事作品，不是人工智能知识介绍站，也不是传统数据大屏。

作品需要用可验证数据、连续叙事和有意义的交互回答一个核心问题：

> 一次智能决策如何被嵌入生产流程，扩散为组织与产业变化，并最终转化为可持续的新质生产力？

作品应同时做到：

- 讲清楚从生产要素到生产结果的因果链；
- 通过真实案例区分节约型、增效型和创造型生产力；
- 让用户通过模拟器验证“AI投入不等于生产力提升”；
- 展示就业、能源、数据与算法风险，避免单向技术乐观主义；
- 形成适合课堂展示和五分钟讲解视频的视觉记忆点。

## 2. 核心观点

AI首先降低识别、预测、生成和决策的成本。当这些低成本决策被大量嵌入生产流程，流程和组织才会发生改变。只有当数据、流程、人员与治理共同适配时，AI能力才能转化为可持续生产力。

完整因果链为：

```text
数据 + 算力 + 算法
        ↓
识别 + 预测 + 生成 + 决策
        ↓
智能判断进入研发、生产、管理与服务流程
        ↓
等待、返工、资源配置和创新搜索方式改变
        ↓
成本、周期、质量和能力边界发生变化
        ↓
产业结构、岗位任务和社会代价发生变化
        ↓
治理决定这种生产力能否持续
```

## 3. 叙事主线

### 3.1 故事主角

全站的视觉主角是一个橙色“决策脉冲”。它代表一次AI判断，并在六幕叙事中持续存在：

- 开场：一次喷或不喷的判断；
- 要素汇聚：数据、算力和算法共同形成的AI能力；
- 流程重构：进入生产流程的控制信号；
- 产业扩散：在不同行业迁移的通用能力；
- 生产力实验室：用户可以调节的生产变量；
- 风险与结尾：必须由人类约束和负责的决策能力。

Three.js场景不是章节装饰，而是同一个对象随故事不断演化。

### 3.2 情绪曲线

```text
好奇：一次判断是怎么发生的？
惊讶：同类判断可以被规模化复制。
理解：规模化判断会改变生产流程。
兴奋：AI可以创造过去难以完成的新任务。
参与：如果由我配置企业，会发生什么？
质疑：增长的成本和风险由谁承担？
思考：我们希望AI替代人，还是扩展人？
```

### 3.3 五分钟视频主线

五分钟讲解视频采用“完整主线 + 一个高光交互”，不承担全站功能导览。行业星图的自由探索、全部案例面板和模拟器公式抽屉保留在网站中，但不在视频中逐项展开。

| 时间 | 视频内容 | 必须讲清的观点 |
| --- | --- | --- |
| 0:00-0:30 | 开场判断与精准喷洒 | 生产力变化始于决策成本下降 |
| 0:30-1:00 | 数据、算力、算法汇聚 | AI能力来自生产要素重新组合 |
| 1:00-1:50 | 传统流程与人机协同流程切换 | 单次判断进入流程后才产生组织价值 |
| 1:50-2:45 | 节约型、增效型、创造型案例 | AI从节约投入发展到扩展能力边界 |
| 2:45-3:45 | 生产力实验室高光交互 | AI投入必须与数据、流程和人员匹配 |
| 3:45-4:30 | 能源、就业与决策责任 | 生产力增长会转移成本和风险 |
| 4:30-5:00 | 替代与增强控制轴、结论 | 治理决定AI能否成为可持续生产力 |

视频中产业星图只作为三个案例向更广产业扩散的转场，不旋转浏览六个行业。网站的探索层不影响五分钟主线的完整性。

视频画面必须直接录制自网站实际运行，可以启用网站内置的高画质模式，但不能用离线渲染、后期合成或另做一套Three.js场景冒充网站效果。剪辑只用于删减等待、添加字幕和组织节奏。若使用尚未实现的概念画面，必须在画面中明确标注“概念演示”，且不能替代核心交互的实际录屏。

## 4. 六幕内容结构

### 4.1 开场：喷，还是不喷

页面从一个具体决策开始。中央是一株植物的抽象点云，页面提出问题：

> 一株植物经过喷杆下方。系统必须在毫秒内判断：这是作物，还是杂草？

用户点击“做出判断”后，摄像头数据进入模型，橙色脉冲沿喷杆传播，仅激活对应喷嘴。镜头随后拉远，显示同类判断被大规模重复。

真实案例采用John Deere See & Spray。案例数据必须标记为厂商披露，不把商业宣传表述为独立研究结论。

本幕结论：

> 生产力的变化，开始于一次决策成本的下降。

### 4.2 要素汇聚：判断如何形成

镜头进入决策脉冲内部。数据、算力、算法三股粒子流进入同一核心，并依次形成识别、预测、生成和决策能力。

用户悬停任一要素时，其他粒子降低透明度，相关路径和解释变量被高亮。任一要素缺失时，系统展示对应失败状态：

- 数据不足：判断不稳定；
- 算力不足：无法进入实时流程；
- 算法不匹配：输入不能形成可靠行动。

本幕回答AI为何不只是一个普通软件工具。

### 4.3 流程重构：判断进入生产

固定视口中的横向流程依次展示研发、生产、管理和服务。垂直滚动控制流程推进。

用户可以切换：

```text
传统流程 → AI辅助流程 → 人机协同流程
```

切换时同时改变等待时间、返工路径、信息回流速度和人工复核节点。页面持续显示周期、成本、质量和创新范围四类结果，但所有数字必须来自真实数据或明确标注为教学模拟。

本幕结论：单次AI判断只有进入流程并改变资源配置方式，才会形成生产力。

### 4.4 产业扩散：三种生产力

案例不按行业平铺，而按生产力层次递进：

| 层次 | AI改变了什么 | 核心案例 | 叙事作用 |
| --- | --- | --- | --- |
| 节约型 | 减少完成同一任务所需投入 | See & Spray精准喷洒 | 降低材料与作业成本 |
| 增效型 | 缩短原有任务完成时间 | GitHub Copilot受控实验 | 改变任务分工与注意力配置 |
| 创造型 | 完成过去难以规模化完成的任务 | AlphaFold蛋白质结构预测 | 扩展科研能力边界 |

三个案例结束后，镜头拉远形成行业星图。第一版只允许3-4个数据充分的行业进入星图，优先从制造、医疗、农业和科研中选择。行业数量由数据完整性决定，不为凑齐六个行业增加装饰节点。

点击行业节点时，高亮该行业依赖的识别、预测、生成、决策和人工复核组合，并打开包含问题、介入位置、流程变化、结果和来源的案例面板。

行业节点的准入条件为：至少一个已核验案例、一个可追溯结果指标，以及一组可解释的能力标签。节点大小或连线粗细只有在指标来自同一数据集、统计年份与口径可比时才映射数值。若没有统一可比指标，节点保持等大，连线只表达能力共享关系并明确标为分类关系，不伪装成数量关系。

### 4.5 生产力实验室：用户亲自验证

页面提出反问题：

> 既然案例有效，是不是投入越多AI越好？

第一版先实现最小可用模拟器，只保留四个归一化参数：

- AI投入强度 `I`；
- 数据准备度 `D`；
- 流程适配度 `P`；
- 人员训练度 `H`。

第一版只输出一个“有效生产力指数”和一个状态解释。模型使用互补性而不是随机数：

```text
I、D、P、H ∈ [0, 1]
协同基础 C = (D × P × H)^(1/3)
有效收益 = I × C
转型摩擦 = I × (1 - C)
有效生产力指数 = 100 × [1 + 0.45 × 有效收益 - 0.30 × 转型摩擦]
```

`0.45`和`0.30`是明确标注的教学设计权重，不宣称为经验估计。这个公式自然产生70-145的指数范围，不额外使用随机扰动或隐藏修正。所有输入相同则输出完全相同。几何平均意味着任一基础条件过低都会形成瓶颈，避免高投入自动得到高产出。

状态不是预先绑定到三个按钮，而是由连续量产生：

1. 当`I < 0.20`时，解释为“尚未形成规模效应”，避免把低投入误判成人机协同；
2. 当`I ≥ 0.20`且有效收益大于等于转型摩擦时，解释为“人机协同”；
3. 当`I ≥ 0.20`、转型摩擦大于有效收益，且`H ≤ min(D, P)`时，解释为“自动化陷阱”；
4. 其余转型摩擦占优的情况解释为“技术孤岛”，并指出数据或流程中数值更低的瓶颈。`D = P`时同时显示两个瓶颈。

每个状态解释都必须包含三个部分：

1. 当前瓶颈参数，例如“人员训练度是当前最低项”；
2. 因果链位置，例如“模型已经进入流程，但人工复核和协作能力未同步形成”；
3. 一个可操作建议，例如“先提高培训投入，再继续提高AI投入”。

状态文案不能只显示标签。实现后邀请5名未参与开发的同学完成盲测：看到状态解释后，应能在20秒内指出主要瓶颈，并选择正确的优先调整参数。至少4人成功才算通过。若未通过，先改文案和视觉指向，不增加模型复杂度。

参数区间、权重和状态判定均纳入单元测试。模拟器必须标记为“教学情景模型，不是企业预测”，并允许展开查看公式、权重和假设。只有当数据台账为参数提供来源或明确记录为设计假设后，参数才可进入正式页面。

单位成本、交付周期、创新能力、治理投入等多输出和多参数属于第二阶段扩展，只有最小模型通过可解释性、稳定性和用户测试后才加入。

### 4.6 增长的阴影与最终选择

生产力曲线上升后，页面暂停并提出：

> 如果计算没有消失，成本被转移到了哪里？

三维核心产生四条裂缝，分别对应：

- 就业与任务重构；
- 算力与能源消耗；
- 数据安全；
- 算法偏见与决策责任。

用户可以切换“无治理扩张”和“负责任采用”，观察培训、人工复核、能源效率和数据治理如何改变风险路径。

最终控制轴为“自动替代 ↔ 能力增强”：

- 只追求替代时，网络更简单、速度更快，但创新节点减少；
- 强调增强时，网络更复杂，需要培训和治理，但出现更多新任务；
- 完全拒绝AI时，风险较低，但效率和能力边界保持不变。

最终结论：

> AI不是天然的生产力。只有当它被嵌入合适的流程，被人正确使用，并受到有效治理时，智能能力才会转化为可持续的新质生产力。

## 5. 视觉系统

### 5.1 设计定位

这是一个全新建设的单页互动数据纪录片，面向课程评审，采用工业编辑式暗色视觉和实验性滚动叙事。

设计参数：

- `DESIGN_VARIANCE: 9/10`
- `MOTION_INTENSITY: 9/10`
- `VISUAL_DENSITY: 6/10`

### 5.2 色彩

- 主背景：`#080A0C`
- 次级表面：`#11161A`
- 主文字：`#ECEBE4`
- 次级文字：`#899197`
- 强调色：`#F26A2E`
- 网格与分隔：白色8%-14%透明度

橙色表示被激活的生产力。未经AI重构的对象保持灰色。页面不使用常见的紫蓝AI渐变，不使用彩虹行业配色。

### 5.3 字体与形态

- 中文标题：MiSans Heavy或思源黑体Heavy；
- 中文正文：MiSans Regular或思源黑体Regular；
- 数字与参数：IBM Plex Mono；
- 内容容器统一使用12px圆角；
- 参数控件可以使用胶囊形，但不把所有内容包装成玻璃卡片；
- 页面维持统一暗色主题，不在章节间切换亮暗模式。

### 5.4 导航

顶部使用不超过64px的固定导航：

```text
引擎 / 重构 / 产业 / 实验室 / 代价 / 结论
```

导航下方显示细线式章节进度。桌面端始终保持单行。移动端收起为当前章节和菜单按钮。

### 5.5 决策脉冲形态规范

决策脉冲必须在完整场景制作前完成跨幕形态原型。其固定视觉基因包括：

- 始终使用熔融橙作为激活色；
- 始终保留一个明亮内核、一圈薄环和一段方向拖尾；
- 材质保持细粒子与精密线框结合，不切换成写实火焰、液体或卡通形态；
- 运动遵循“聚集、压缩、释放、回稳”的同一节奏；
- Bloom只强化内核，不形成大面积霓虹外发光；
- 无论尺度如何变化，用户都能通过内核、薄环和拖尾识别它是同一个对象。

各幕只改变允许变化的属性：

| 场景 | 保持不变 | 允许变化 |
| --- | --- | --- |
| 开场判断 | 内核、薄环、拖尾 | 缩小为沿喷杆移动的信号 |
| 要素汇聚 | 颜色、材质、脉冲节奏 | 三股输入流汇入薄环 |
| 流程重构 | 内核和方向拖尾 | 拉伸为在流程管线中移动的控制信号 |
| 产业扩散 | 每个激活节点的薄环特征 | 复制为多个行业节点并形成关系 |
| 生产力实验室 | 内核、颜色和节奏 | 环的稳定度和拖尾长度响应模型结果 |
| 风险与结尾 | 内核始终存在 | 薄环断裂、重连并与人的节点结合 |

在开发完整场景前，先完成六帧静态故事板，再制作一个只覆盖“开场判断 → 流程重构”的动态测试场景。两个极端形态必须共享真实实现中的内核、薄环、拖尾和运动缓动。这个原型用于同时验证静态识别性与运动节奏，不提前制作六幕完整场景。

早期验收问题为：不依靠文字说明，观察者能否认出两个动态形态和六帧故事板表现的是同一个决策脉冲。如果不能，先修订形态规范，不继续堆叠场景特效。

## 6. 动效与交互职责

### 6.1 Three.js场景

负责：

- 粒子汇聚；
- 决策核心形态变化；
- 产业关系网络；
- 镜头路径；
- 轻量选择性Bloom；
- 点击和悬停的三维拾取。

全站使用一个持续存在的Canvas，通过章节状态改变场景，不为每一幕重新创建WebGL上下文。

### 6.2 GSAP ScrollTrigger

负责：

- 章节钉扎；
- 滚动进度与镜头进度同步；
- 横向流程推进；
- 关键文本和图表进入时机；
- 三维场景状态之间的连续过渡。

不增加额外平滑滚动库，不监听原始`window.scroll`持续写入React状态。

### 6.3 D3与DOM

- `d3-force`计算行业关系网络初始布局；
- `d3-scale`完成真实数据到视觉尺寸的映射；
- SVG或Canvas负责精确二维图表；
- CSS负责按钮反馈、文字遮罩和普通悬停；
- React负责章节、案例和模拟参数状态。

同一元素不由多个动画系统同时控制。

## 7. 数据与案例规范

开发的第一个交付物不是图表，而是数据台账。台账建议保存为`src/data/data-ledger.json`，每一条可视化声明都必须先在台账中通过核验，再进入页面。

每一条数据记录包含：

```text
id / claim / value / unit / year / geography / industry / methodology
sourceTitle / sourceUrl / originalDocumentUrl / sourceType
verificationStatus / checkedAt / caveats / independentCorroboration
```

来源类型分为：

- 官方统计；
- 学术或研究报告；
- 企业披露；
- 教学情景模拟。

所有图表旁显示年份、单位和来源入口。页面提供统一的数据来源抽屉，并允许从图表直接定位相应条目。

核验状态只允许：

- `verified`：已打开原始来源并核对数值、单位、年份和范围；
- `qualified`：来源可用，但仅为企业披露或存在明显口径限制；
- `pending`：尚未完成核验，不得进入正式页面。

第一版允许`verified`和`qualified`数据进入页面，但二者的视觉表达必须不同：

- `verified`显示常规来源标记；
- `qualified`在数值旁显示“有限证据”标记；
- 当`independentCorroboration`为空时，展开说明必须显示“当前仅有单一来源，尚未找到独立佐证”；
- 企业或平台披露还必须显示来源主体，例如“厂商披露：John Deere”；
- `pending`既不能生成图表，也不能出现在正式构建的数据文件中。

“有限证据”标记不能只藏在来源抽屉中。用户不展开详情时，也应能从数字旁辨认其证据等级。

数据台账的开发门槛为：

1. John Deere数据优先寻找独立研究佐证；若没有，只以`qualified`状态显示并标注“厂商披露”；
2. GitHub Copilot数据回到实验方法与样本范围，不把特定任务实验外推到全部软件开发；
3. AlphaFold数量回到原始论文、数据库或EMBL-EBI材料核对，不只引用项目营销主页；
4. IEA能源数据追溯到正式报告的表格、年份与地区范围，不只引用新闻稿；
5. 行业星图所需的可比指标必须来自同一来源体系，否则不用于节点大小或连线粗细；
6. 模拟器的参数区间与权重分别记录“外部证据”或“教学假设”，二者不得混写。

## 9. 性能与可访问性

### 9.1 性能等级

- 高性能桌面：约8,000-15,000个实例粒子，开启轻量Bloom；
- 普通设备：降低像素比、粒子数量和后期效果；
- 手机：约1,500-3,000个粒子，关闭景深和复杂后期；
- 低帧率设备：自动进入简化模式；
- 页面隐藏时暂停渲染；
- WebGL不可用时展示预渲染静态关键帧。

优先复用几何体和材质，粒子与重复节点使用实例化，动态分辨率上限默认不超过1.5 DPR。

量化性能目标：

- Lighthouse移动端Performance不低于70；
- Lighthouse Accessibility不低于90；
- 低性能模式粒子数不超过3,000，关闭Bloom和景深后，在当前开发电脑Chrome中连续运行30秒的中位帧率不低于30fps；
- 主线程不存在持续超过200ms的交互阻塞；
- App Shell显示后5秒内首屏三维资源仍未就绪或加载失败时，自动切换静态关键帧，不显示无限加载动画；
- 性能测试必须记录浏览器版本、视口、设备和模式，避免只保留一个脱离环境的fps数字。

### 9.2 可访问性

- 所有主要交互均可使用键盘；
- 三维可视化同时提供文本摘要；
- 图表不依赖颜色作为唯一编码；
- 正文与控件满足WCAG AA对比度；
- `prefers-reduced-motion`下取消镜头飞行、视差、持续旋转和滚动绑定；
- 焦点状态始终可见；
- 移动端不强制横向滚动劫持。

## 10. 错误与降级状态

- 数据文件加载失败：保留章节结构，显示可读错误和重新加载入口；
- 单条来源缺失：隐藏该数字，不用占位数字替代；
- Three.js初始化失败：切换到静态海报和SVG图表；
- 低性能模式：保留全部信息与交互，只减少粒子和后期特效；
- 模拟参数非法：在参数旁显示范围提示，不更新结果；
- 来源链接失效：在来源抽屉标记为待核验，不继续显示为已验证来源。

## 11. 响应式策略

- 桌面端使用固定Canvas、章节钉扎和横向流程；
- 平板端减少镜头位移，横向流程改为可控分段切换；
- 小于768px时取消复杂非对称布局，正文改为单栏；
- 行业星图在手机上固定改为“行业列表 + 能力关系图”：行业使用纵向单选列表，选择后在下方展示识别、预测、生成、决策和人工复核的能力链条及案例摘要；不实现可拖拽平面网络；
- 模拟器在手机上先显示参数，再显示结果，提供固定“查看结果”入口；
- 所有章节使用`100dvh`相关布局，避免移动浏览器地址栏导致跳动。

## 12. 验收标准

### 12.1 叙事

- 用户能复述“一次判断如何成为生产力”的因果链；
- 三个案例分别支持节约、增效和创造三个层次；
- 风险章节与前文因果相连，不是附加伦理列表；
- 最终结论强调人、流程和治理，而不是技术决定论。
- 五分钟视频能在不展开星图探索层的情况下完整讲完主线；
- 视频至少完整展示一次传统流程与人机协同流程切换，以及一次模拟器参数变化。
- 视频中的核心画面均来自网站实际运行录屏，高画质模式仍是同一套运行时代码；
- 未实现的概念画面如被使用，均有清晰的“概念演示”标记。

### 12.2 数据

- 页面中不存在无来源的精确数字；
- 企业披露、研究结论和教学模拟有明显区别；
- 每条来源都有年份、范围、单位和可访问链接；
- 模拟模型的公式与假设可见。
- 所有页面数字在数据台账中为`verified`或带限制说明的`qualified`；
- 产业星图只包含满足案例、结果指标和能力标签准入条件的行业；
- 企业披露无法获得独立佐证时，页面必须明确显示其来源性质。
- `qualified`数据在数值旁显示“有限证据”，独立佐证为空时显示“当前仅有单一来源”；
- 第一版的数据合格线是`verified`或显式披露限制的`qualified`，不强求所有数据达到`verified`。

### 12.3 视觉与动效

- 全站使用一个持续演化的三维核心；
- 每项主要动效都能解释其叙事职责；
- 不使用AI紫渐变、装饰性粒子墙和重复三栏卡片；
- 页面暗色主题、强调色、圆角和字体系统一致；
- 减少动效模式仍能完整阅读和操作。
- 六幕中的决策脉冲都保留内核、薄环和拖尾三个识别特征；
- 六帧故事板和“开场判断 → 流程重构”动态原型通过“无文字仍能识别为同一对象”的早期检查；
- 行业星图中视觉尺寸和连线粗细不存在无数据支持的数量暗示。

### 12.4 工程

- 桌面和手机均能完成全部核心路径；
- 低性能设备自动降级且不丢失信息；
- Three.js、GSAP和D3不重复控制同一元素；
- 构建通过，无控制台错误；
- GitHub Pages刷新和资源路径正常；
- Lighthouse移动端Performance不低于70，Accessibility不低于90；
- 低性能模式粒子数不超过3,000，连续30秒中位帧率不低于30fps；
- 键盘可完成开场判断、流程切换、模拟器调节、风险模式切换和最终控制轴；
- 模拟器固定输入产生固定输出，四种状态及边界值均有自动化测试覆盖；
- 5名未参与开发的同学参加状态解释盲测，至少4人能在20秒内指出瓶颈并选择正确的优先调整参数；
- 数据台账校验能够阻止`pending`数据进入正式构建。

## 13. 明确不做

- 不做多页面门户；
- 不做用户登录、后台或数据库；
- 不做无来源的实时数字大屏；
- 不把六个行业做成六张同构卡片；
- 不加入与叙事无关的小游戏；
- 不自动播放声音；
- 不为炫技加入全站自定义鼠标、双重滚动系统或持续故障特效；
- 不在第一版制作复杂三维工业城市和大量外部3D模型。
- 不在最小模拟器验证前加入多输出雷达图、七个参数和随机扰动；
- 不在缺乏统一可比数据时把行业节点大小或连线粗细伪装成统计编码。

第一版的复杂度集中在一条完整故事、一个持续场景、三类真实案例、一个四参数单输出的透明模拟器、3-4个有数据支撑的行业节点和一套可靠降级机制。
