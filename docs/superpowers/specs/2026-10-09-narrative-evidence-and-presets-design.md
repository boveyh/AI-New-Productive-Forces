# 连续案例、证据剧场与实验室预设设计

## 1. 改造目标

本轮不改变网站现有的六节点因果链，也不增加新的独立章节。改造要解决四个问题：

1. 开场只提出“喷，还是不喷”，没有说明喷的是除草剂、系统在识别什么，也没有继续用该案例解释后续机制；
2. 开场结束后直接进入企业AI采用率，微观判断与宏观扩散之间缺少尺度变化；
3. “结果改变”章节虽然列出数据，但案例仍像并列卡片，结果数字与流程机制没有形成足够强的证据链；
4. 章节过渡主要依靠“一句结论加一句提问”，重复使用后产生节奏和审美疲劳。

改造后的前半程以精准农业为贯穿案例：从一次除草剂喷洒判断开始，依次解释判断复制、采用扩散、要素重组、流程重构和结果改变。完成农业案例闭环后，叙事才向软件研发、客户服务、制造和科学研究扩展。

## 2. 叙事边界

### 2.1 精准农业贯穿范围

精准农业贯穿以下六个连续动作：

`田间情境 → 一次判断 → 判断复制 → 要素咬合 → 流程闭环 → 除草剂投入改变`

它在“结果改变”章节完成闭环。行业扩展从此处开始，不强行让农业案例继续承担实验室和治理章节的全部解释。

### 2.2 主因果链保持不变

网站仍使用同一条因果链：

`判断成本下降 → AI进入任务 → 要素重组 → 流程重构 → 结果改变 → 新治理`

新增内容必须服务这条链，不建立第二套目录或第二条平行叙事。

## 3. 开场重构

### 3.1 先交代判断对象

首屏必须在提出问题前后明确说明：

- 作业场景为休耕地定点喷洒；
- 喷洒对象是除草剂，不是水、肥料或农药的泛称；
- 系统需要区分需要清除的杂草与不应触发喷洒的区域；
- 判断结果控制对应喷嘴是否开启。

开场文案不把厂商披露外推为全部农业作业。数据范围继续沿用台账中的场景限定。

### 3.2 四步判断动作

用户启动引擎后，页面不立即滚动到采用率，而是完成四个连续动作：

1. **识别现场**：摄像头画面进入判断区域；
2. **区分目标**：系统标出杂草，并显示一次置信判断；
3. **形成决策**：橙色脉冲选择“喷洒”；
4. **执行动作**：脉冲抵达对应喷嘴，局部喷洒被触发。

四步共享同一条线与同一个决策脉冲。每一步显示一个失败后果：看不清、来不及、分错目标、执行错位。

失败后果不只作为警告文案出现，而要形成一次可见的“成本回流”：失败节点的脉冲转为灰白色，沿原路径反向回到人工处理节点，并依次出现“重新观察”“重新判断”“重新操作”等短促辅助文字；成功状态下，脉冲保持橙色并继续向喷嘴推进。由此明确：判断成本下降不是某一步简单替代了人，而是观察、判断和执行组成的完整链条能够低成本重复。任何一步失效，需要人重新接管，成本就重新回到生产过程。

人工处理节点固定在判断区域右下方的主路径外侧，视觉上使用一个简化的“手动复核台”：细线方框、Phosphor图标库的`UserFocus`图标和“人工复核”文字组成同一个低对比节点。四步动作共享这一节点，只有发生失败或用户主动查看失败路径时才提高亮度；成功状态下保持隐藏。它不与因果状态条或四步动作节点重合，也不计入主因果链，避免被理解成第七个因果节点。

动态辅助文字只在状态变化时出现，每次不超过十个汉字，不与主标题同时争夺视觉中心；减少动态效果模式下改为节点旁的静态说明。

### 3.3 从一次判断到判断流

四步结束后镜头从单株判断拉远到整条喷杆。同一个判断点复制成连续决策流，并出现核心结论：

> 真正改变生产力的，不是机器判断对了一次，而是同类判断可以低成本、高频率地重复。

这段视觉同时承担从开场到采用率章节的过渡。

## 4. 采用率章节的进入方式

### 4.1 尺度放大

采用率图表不能作为一个突然出现的新主题。田间的多个判断点在同一画布中重新排列为企业采用率数据点，语义从“一个设备重复判断”放大为“更多企业开始把AI判断放进任务”。

采用率章节回答两个问题：

- 有多少企业已经开始使用至少一种AI技术；
- 为什么采用深度会因企业规模、任务类型和地区条件而不同。

采用率只表示AI进入任务的广度，不直接代表生产率已经提高。

### 4.2 农业案例继续作为解释锚点

四个采用率场景旁保留一个轻量“田间回声”：

- 总体采用率对应“有多少组织开始复制智能判断”；
- 企业规模差异对应“谁有能力准备数据、设备和人员”；
- 技术类型差异对应“AI进入了什么任务”；
- 国家差异对应“同样技术落在不同生产条件中”。

“田间回声”不是重复卡片，只以短注释或图中标注出现。

## 5. 要素与流程章节的案例映射

### 5.1 要素不再只用抽象齿轮解释

数据、算力和算法的视觉机械结构保留，但标签必须同时映射到农业任务：

| 要素 | 农业任务中的作用 | 降低后的可见故障 |
| --- | --- | --- |
| 数据 | 摄像头是否看清植物与地面 | 目标轮廓缺失，判断区域断裂 |
| 算力 | 设备驶过前能否完成识别和决策 | 脉冲堆积，错过喷嘴窗口 |
| 算法 | 能否区分杂草与非目标区域 | 路径错误分叉，喷洒对象混淆 |

故障动画本身解释因果，不依赖弹出一段错误文字。

### 5.2 流程比较继续使用同一个任务

流程对比改为同一项除草作业的三种组织方式：

- **传统流程**：先观察区域，再按区域统一喷洒；
- **AI辅助**：AI提供识别结果，但执行与复核仍集中在流程末端；
- **人机协同**：识别、局部执行、异常复核和结果反馈形成闭环。

流程图必须让用户看到AI介入位置改变后，等待、返工、复核与反馈节点怎样移动。

## 6. 结果章节改为证据剧场

### 6.1 选择理由

案例不使用五张同构卡片，不使用把不同统计口径放在同一坐标轴上的排名图，也不使用重复的全屏卡片栈。采用“一次聚焦一个案例”的证据剧场，并在底部保留紧凑案例轨道。

### 6.2 五个案例的递进关系

五个案例不按行业、数字大小或技术先进程度排序，而按AI判断进入任务的深度排列。深度轴依次为：

`一次执行 → 一个任务 → 一组经验 → 一条流程 → 一类新任务`

它描述的是AI从改变局部动作，逐渐进入知识传递与流程结构，最终扩展任务边界的过程。这条深度轴对应主因果链中的“AI进入任务 → 流程重构 → 结果改变”，不是新的平行分类体系。

| 生产力层次 | 案例 | 核心变化 |
| --- | --- | --- |
| 节约投入 | See & Spray精准喷洒 | 整片喷洒变为识别后局部执行 |
| 缩短任务 | GitHub Copilot受控任务 | 生成进入编码任务，人的时间移向验证 |
| 传递经验 | NBER客服现场研究 | 优秀员工经验变成实时建议 |
| 重构流程 | 贵州轮胎灯塔案例 | 检测与工艺数据回到生产现场形成反馈 |
| 扩展边界 | AlphaFold数据库 | 难以规模化获得的结构预测变成公共研究资源 |

这五项数据口径不同，不进行统一大小排名。

### 6.3 单个案例的固定信息结构

每个案例必须回答：

`原来怎么做 → AI判断什么 → 流程哪里改变 → 结果如何衡量 → 证据有什么限制`

桌面布局：

- 左侧：介入前与介入后的流程叠影；
- 中央：同一决策脉冲在流程节点间移动；
- 右侧：一个核心数字、统计对象、年份和证据等级；
- 底部：案例轨道与来源入口；数据口径和案例特有限制收进可展开的证据抽屉。

手机布局改为纵向顺序，不压缩成三列。

### 6.4 数字呈现规则

数字必须同时显示统计对象和指标，不允许只显示“77%”“55.8%”等孤立大数字。精准农业案例应呈现为：

- 统计对象：See & Spray Select休耕地定点喷洒场景；
- 改变对象：除草剂投入；
- 机制：识别杂草后开启对应喷嘴；
- 结果：厂商披露平均节省77%的除草剂；
- 限制：不能外推到所有作物、设备和农业作业。

企业披露继续标记“有限证据”，研究或官方来源按台账状态显示。

证据剧场顶部只显示一次页面级说明：“案例统计对象与指标不同，用于解释机制，不进行统一排名。”单个案例默认仅显示“有限证据”“研究来源”或“官方来源”标识。展开证据抽屉后才显示该案例特有的样本、口径和限制，不在默认画面重复页面级声明。

## 7. 从农业到行业扩展

五个案例完成后再出现行业关系图。它不重复案例介绍，只回答“同一种低成本判断进入不同任务后，为什么产生不同结果”。

证据剧场与行业关系图承担不同层次的任务：证据剧场证明五个真实案例分别改变了什么；行业关系图把案例暂时收束为识别、预测、生成、决策、执行和复核等共享能力，解释相似的低成本判断为何在不同任务约束下产生不同结果。转场时，五个案例的流程线先折叠为共享能力节点，再重新连接到行业，而不是重新出现第二组案例卡片。

折叠动画使用固定的六个共享能力节点：`识别、预测、生成、决策、执行、复核`。每个案例至少连接其中两项，流程线沿当前案例路径回收后落到这些固定坐标，再从共享节点向行业展开。能力名称和顺序只在一份常量表中定义，证据剧场、行业关系图与折叠动画共同消费，不建立第二套能力分类。

首批案例映射固定为：

| 案例 | 共享能力节点 |
| --- | --- |
| See & Spray精准喷洒 | 识别、决策、执行、复核 |
| GitHub Copilot受控任务 | 生成、执行、复核 |
| NBER客服现场研究 | 生成、决策、复核 |
| 贵州轮胎灯塔案例 | 识别、预测、决策、执行、复核 |
| AlphaFold数据库 | 预测、生成、复核 |

选择行业后显示三层：

1. AI在判断什么；
2. 判断嵌入哪个流程节点；
3. 最终改变成本、周期、质量还是任务边界。

行业节点的视觉大小不映射不可比数据。点击节点展开一个来自证据剧场的案例摘要和能力路径。

## 8. 实验室情景预设

### 8.1 四个固定搭配

实验室增加四个一键情景：

| 情景 | AI投入 | 数据准备 | 流程适配 | 人员训练 | 解释目标 |
| --- | ---: | ---: | ---: | ---: | --- |
| 谨慎试点 | 16 | 42 | 38 | 46 | 投入尚不足以改变整个流程 |
| 技术孤岛 | 76 | 24 | 32 | 68 | 技术投入与数据、流程脱节 |
| 自动化陷阱 | 82 | 76 | 70 | 18 | 自动化扩张快于培训和复核能力 |
| 人机协同 | 74 | 80 | 76 | 72 | 四项条件互补，收益超过摩擦 |

预设只写入四个输入值。状态、指数、瓶颈、有效收益和转型摩擦仍由现有纯函数计算，不能在预设按钮中硬编码结果。

### 8.2 点击反馈

点击预设后：

1. 四条滑杆同步移动；
2. 变化幅度最大的条件先高亮；
3. 当前最低条件显示瓶颈标记；
4. 结果按“投入 → 协同基础 → 有效收益与转型摩擦 → 状态”顺序更新；
5. 页面提示用户仍可手动微调，观察跨越阈值后的变化。

在减少动态效果模式下，数值直接切换，不播放滑杆补间，但上述信息仍完整显示。

四个预设不表达从低到高的推荐等级，而是展示四种典型结构。实验室的共同结论是：总投入不能补偿结构性短板，显著落后的数据、流程或人员条件会把投入转化为摩擦；只有四项条件形成互补，有效收益才可能稳定超过转型摩擦。

预设按钮下方增加一行随状态变化的动态辅助文字，不复述状态名称，而直接指出结构关系，例如“投入先走，数据和流程仍未接通”“模型已经进入流程，复核能力没有跟上”。辅助文字由当前计算结果中的瓶颈与因果位置生成，不为每个按钮另写一套结论。

## 9. 转场语法

Story Bridge不再统一渲染为“一句结论加一句提问”。七个章节连接轮换使用四种视觉语法：

### 9.1 形态重组

同一组视觉单元换坐标系。用于开场到采用率：田间判断点重组成企业采用率数据点。

### 9.2 对象接力

上章末端对象直接成为下章输入。用于采用率到要素、要素到流程：数据点拆为三路信号，故障路径继续延伸为流程电路。

### 9.3 前后叠影

同一任务的旧流程与新流程重叠比较。用于流程到结果：路径变化后，成本、周期、质量或任务边界指标从对应节点显现。

### 9.4 约束显影

收益扩大时，摩擦和风险从背景进入前景。用于结果到实验室、实验室到治理、治理到结论。

### 9.5 文案规则

- 转场文案最多两行，但不强制每次包含问句；
- 问句最多出现在七个转场中的三次；
- 其余转场使用动作标签、尺度变化说明或因果短句；
- 当前因果节点仍由固定状态条显示，不另建第二套导航；
- 手机端保留转场含义，但取消复杂路径重组。

## 10. 数据结构

### 10.1 四步判断数据

四步动作使用同一份结构化数据驱动节点、成本回流文字和测试：

```ts
type DecisionStep = {
  id: 'observe' | 'classify' | 'decide' | 'execute'
  label: string
  failure: string
  humanFallback: string
  causalNode: 'decision'
  humanFallbackNodeId: typeof humanFallbackNodeId
}
```

```ts
export const humanFallbackNodeId = 'human-review-station' as const
```

`causalNode`固定为`decision`，四步的`humanFallbackNodeId`固定指向同一个外围节点，避免在代码中演变成四条独立因果线或四个人工节点。`humanFallbackNodeId`不得出现在主因果链节点常量中。

### 10.2 案例数据

从`App.tsx`内联案例数组中抽出结构化案例数据，至少包含：

```ts
type EvidenceCase = {
  id: string
  layer: 'saving' | 'speed' | 'transfer' | 'restructure' | 'creation'
  causalNodes: Array<'task' | 'process' | 'results'>
  capabilities: SharedCapability[]
  before: string
  aiDecision: string
  processChange: string
  outcome: string
  metricLabel: string
  ledgerId: string
}
```

共享能力使用唯一常量表：

```ts
export const sharedCapabilities = ['识别', '预测', '生成', '决策', '执行', '复核'] as const
type SharedCapability = (typeof sharedCapabilities)[number]
```

每个案例的`capabilities`至少包含两项，所有值必须来自`sharedCapabilities`。

来源、年份、地域、统计口径和限制继续从`data-ledger.json`读取，不重复维护。

### 10.3 实验室预设

预设保存为普通常量并复用`ProductivityInputs`：

```ts
type LabPreset = {
  id: string
  label: string
  explanation: string
  inputs: ProductivityInputs
}
```

不新增状态管理库，不引入新的动画依赖。继续使用React本地状态、现有GSAP和原生CSS过渡。

## 11. 测试与验收

### 11.1 叙事验收

- 用户在首屏二十秒内能回答：喷的是除草剂、判断对象是什么、结果控制哪个执行部件；
- 开场到采用率之间存在可见的“判断复制与尺度放大”，不能直接硬切；
- 精准农业案例在要素、流程和结果章节都有明确回指；
- 农业案例完成结果闭环后才扩展到其他行业。
- 四步判断动作共享“判断成本下降”节点；任一步失败时都能看到处理成本回流到人工节点，而不是四段互不相关的动画。
- 四步失败路径的终点必须是同一个`humanFallbackNodeId`，且该ID不属于主因果链节点集合；成功路径不激活人工处理节点。

### 11.2 案例验收

- 五个案例均具备介入前、AI判断、流程改变、结果指标和证据限制；
- 每个大数字旁可直接看到统计对象与指标；
- 不同口径数据不共享排名轴；
- 企业披露与有限证据状态保持可见。
- 五个案例的`layer`必须映射到“AI进入任务、流程重构、结果改变”中的至少一个节点，并按任务进入深度排列；不允许加入无法解释其因果位置的案例。
- 五个案例的能力映射必须来自同一份`sharedCapabilities`常量，每个案例至少映射两项；折叠动画与行业关系图不得自行声明能力名称或顺序。
- 页面级不可比声明只出现一次，单个案例默认不展开长篇限制说明。

### 11.3 预设验收

- 四个预设精确写入规格表中的四组输入；
- 预设结果完全来自`evaluateProductivity`；
- 选择预设后仍可继续手动调节；
- 当前预设、最大变化项和瓶颈对键盘及屏幕阅读器可感知；
- 为四个预设增加纯函数回归测试，确认它们分别落在预期状态。

### 11.4 转场验收

- 七个转场至少使用三种不同视觉语法；
- 问句不超过三次；
- 不出现连续三个相同布局的Bridge；
- 减少动态效果时，转场退化为静态因果短句，不丢失信息；
- 移动端不依赖悬停，案例轨道和预设均可触摸操作。

### 11.5 工程验收

- `npm test`、`npm run lint`、`npm run build`和`npm run check:data`全部通过；
- 不新增运行时依赖；
