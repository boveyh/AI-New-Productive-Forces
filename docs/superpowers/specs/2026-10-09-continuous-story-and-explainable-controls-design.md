# 连续叙事与可解释控制设计

## 目标

现有网站已经具备独立的动态图表、要素机械、流程电路、案例、模拟器和治理环，但章节之间仍像多个演示模块。此次改造要让评审在进入页面后的前二十秒内理解主问题，并在全程持续看到同一条因果链：

`判断成本下降 → AI能力进入任务 → 生产要素重新组合 → 流程被重构 → 生产结果改变 → 新风险要求新治理`

网站继续以精准农业中的“喷，还是不喷”为贯穿案例。它不是唯一案例，而是一条用于理解所有章节的叙事线索。

## 一、修复 Remotion 国家场景

- Composition 顶部固定保留标题区，数据绘图区不得进入标题区。
- 国家排行首行从标题区下方开始，七个国家在剩余高度内等距排列。
- “同一项技术，落在不同的生产土壤里”保留为章节判断，不覆盖“丹麦”等数据标签。
- 桌面端、窄屏横向视图和 15fps 降级模式使用同一安全边距。

验收：任意帧率与四种时间轴控制状态下，标题、国家名、数值标签均不重叠。

布局不依赖人工目测。Composition 使用统一安全区常量计算标题底线、国家行坐标和数值标签右边界，并对桌面、窄屏横向、15fps降级三种布局在首帧、中间帧、末帧生成布局快照。测试必须断言：标题区底部小于第一行顶部、相邻行间距为正、数值标签右边界小于容器右边界。

## 二、建立贯穿全站的叙事主线

### 开场铺垫

在“喷，还是不喷”前增加三层信息：

1. 过去，扩大生产通常意味着增加更多土地、设备和劳动；
2. AI带来的变化，是把部分判断变得更快、更便宜、更可复制；
3. 网站将追踪一个田间判断，观察它如何变成生产力。

开场仍保持短促，不增加说明书式长文。

### 章节桥接

每个主要章节之间增加轻量 Story Bridge，固定回答三个问题：

- 刚刚证明了什么；
- 因果链现在走到哪里；
- 下一章必须回答什么。

桥接不是卡片，不占据完整章节，而是由一条延续的橙色线路、一个短结论和一个具体问题组成。

为防止 Story Bridge 退化，固定以下限制：

- 每条最多一行结论和一行问题；
- 七条 Bridge 复用同一条连续 SVG path，相邻段的终点必须等于下一段的起点；
- 问题必须指向下一章的具体机制，例如“如果判断可以复制，数据、算力和算法中哪一项会先成为瓶颈？”，不得使用“接下来我们将看到”等目录式文案；
- Bridge 不提供章节跳转，避免与导航和因果状态条重复；
- 375px 下默认只显示问题，点击后展开结论，完整文本仍可被键盘和读屏访问。

桥接顺序：

1. 判断产生后：一次正确判断还不是生产力，它必须可以复制；
2. 采用率之后：企业买到AI不等于获得生产力，还需要数据、算力和算法咬合；
3. 要素之后：能力具备后，决定结果的是它进入流程的位置；
4. 流程之后：流程变化必须在成本、质量、速度或新任务上留下证据；
5. 案例之后：局部成功能否扩大，取决于投入与组织条件的互补；
6. 模拟器之后：规模越大，错误、能源和责任也传播得越快；
7. 治理之后：治理不是生产力的反面，而是生产力能够持续的条件。

### 持续定位

导航下方增加始终可见的极简因果链状态条：

`判断成本 ↓ → AI进入任务 → 要素重组 → 流程重构 → 结果改变 → 新治理`

每个节点只承担三项功能：

- 当前节点高亮，同时用 `aria-current="step"` 标记；
- hover、键盘聚焦或点击时显示一句“刚刚证明了什么”；
- 点击跳转到对应章节。

因果节点与页面章节使用同一份常量表，不能单独维护第二套标题、锚点或高亮规则。移动端因果条横向滚动并自动把当前节点带入视口，不缩写成无法理解的图标。

## 三、统一滑杆为可解释实验仪器

### 共享状态模型

四类滑杆统一消费纯函数解析结果：

```ts
type SliderKind = 'ai-position' | 'productivity' | 'governance' | 'augmentation'

type SliderState = {
  value: number
  stageIndex: number
  stageName: string
  thresholdCrossed: boolean
  metrics: Record<string, number>
  explanation: string
  benefit: string
  cost: string
}

resolveSliderState(
  kind: SliderKind,
  value: number,
  params: Record<string, number>,
): SliderState
```

共享模块同时保存阈值、阶段名称和指标映射。组件只渲染 `SliderState`，不得再次判断 `value < 25` 等区间。这样键盘播报、减少动态效果模式和边界值测试共享同一逻辑。

所有关键滑杆统一包含：

- 可点击的关键节点；
- 当前状态名称；
- 当前参数在因果链中的含义；
- 至少三项同步变化；
- 跨越阈值时的一次性提示；
- 键盘可操作和 `aria-live` 状态播报。

### AI介入位置

四个阶段：

1. `0–24` 流程外建议：AI只提供参考，等待基本不变；
2. `25–49` 局部任务自动化：单点加速，但交接处仍可能返工；
3. `50–74` 流程内协作：生成、复核和执行开始连续；
4. `75–100` 反馈闭环：结果回流上游，系统可以持续校正。

同步指标：任务周期、等待节点、人工复核位置、反馈完整度。

### 生产力实验室

四个输入分别提供低、中、高三个解释区间，并显示当前参数标签。例如数据准备度分为“口径分散、可用但不统一、可追溯资产”。状态结果继续使用现有四状态模型，但增加：距离下一状态的关键参数、阈值提示和四项结果拆解。

结果拆解：产出、周期、摩擦、创新能力。它们是教学模拟值，页面必须继续声明不是企业预测。

### 治理约束

四个阶段：

1. 无约束扩张；
2. 事后审计；
3. 关键节点复核；
4. 可追溯治理。

同步指标：决策速度、错误传播、人工复核、可追溯性、能耗约束。关键节点为 25、50、75。

治理不是“越多越好”，每个阶段必须同时显示收益和代价：

| 阶段 | 收益 | 代价 |
| --- | --- | --- |
| 无约束扩张 | 决策速度快 | 错误传播不可控 |
| 事后审计 | 结果可以追责 | 纠正已经滞后 |
| 关键节点复核 | 高影响风险可控 | 决策速度下降 |
| 可追溯治理 | 系统更可持续 | 前期组织与基础设施成本高 |

### 自动替代到能力增强

四个阶段：任务替代、局部自动化、人机协作、能力扩展。

同步指标：任务速度、人的判断份额、新任务节点、组织连接数。结论不暗示“越靠右越好”，而是强调不同任务需要不同责任结构。

## 四、最终引申：同一机制在四种约束下显影

结尾不是列出四个行业，而是把前文因果链完整运行第二次。精准农业的同一决策脉冲在结尾分裂为四条 SVG 路径，每条路径只显示一个动词变化，点击后展开该领域的因果链与不可压缩约束。

| 路径 | 判断成本下降后 | 流程重构 | 结果改变 | 不可压缩约束 | 新治理 |
| --- | --- | --- | --- | --- | --- |
| 研发 | 搜索已有答案 → 生成并验证候选 | 实验设计从串行变并行 | 候选数量与验证速度改变 | 验证成本 | 验证责任不能外包给生成 |
| 制造 | 事后检测 → 实时反馈 | 工艺调整从事后变在线 | 良率与停机时间改变 | 物理实时性 | 在线调整需要明确权限边界 |
| 医疗 | 信息整理 → 辅助判断 | 判断路径从集中变为协作 | 判断速度与一致性改变 | 责任不可转移 | 高影响责任仍由人承担 |
| 组织 | 层层传递 → 现场判断 | 决策点向现场前移 | 响应速度与连接数改变 | 信息传递损耗 | 决策权与责任同步下沉 |

四条路径使用同一组因果节点数据，只替换领域动作、约束和治理结果，不创建四套独立卡片逻辑。

### 回到那块田

四条路径展开后，脉冲重新汇聚到开场的植物轮廓，形成叙事闭环：

> “喷，还是不喷”曾经是一个只能由人现场承担的判断。判断成本下降后，这个问题没有消失，而是被拆成更多可以复制的小判断。真正的问题不再是AI能不能判断，而是哪些判断可以复制，哪些责任必须留给人。

### 不可复制清单

结尾增加一份极简边界清单，不使用卡片：

- 高影响且不可逆的决策；
- 责任无法转移的判断；
- 高度依赖现场身体经验的任务；
- 涉及价值排序而非事实识别的选择。

它与可复制判断形成并置关系：AI降低可复制判断的成本，让人更集中地承担不可复制的判断，而不是宣称所有判断都应该自动化。

### 最终观点

第一层回答生产力机制：

> AI成为新质生产力，不只是因为它把旧任务做快了，而是因为判断成本下降后，过去无法规模化的新任务、新产品和新组织方式开始成为可能。

第二层明确责任边界：

> 但判断越能被复制，责任就越不能一起被复制。新质生产力的上限，不取决于AI能判断多少，而取决于人愿意为什么样的判断负责。

## 五、实现边界与验收

- 不增加新的动画库；复用 React、GSAP、SVG、Three.js 与 Remotion。
- Story Bridge 使用普通 React 与 SVG，不创建新的全屏 Three.js 场景。
- 因果节点、章节锚点、Bridge内容和最终四路径使用共享常量表；滑杆参数区间与指标映射使用统一纯函数。
- 所有阈值在 0、24/25、49/50、74/75、100 处可稳定复现。
- 减少动态效果模式下取消阈值闪烁与路径运动，但保留全部文本状态。
- 桌面端与 375px 宽度下，Remotion 国家标签、滑杆节点和状态文本不得互相遮挡。
- Remotion 布局快照覆盖四种时间轴状态、三种布局模式和三个关键帧，断言安全区、行间距和右边界。
- Story Bridge 连续性测试断言相邻片段的终点与起点一致。
- 滑杆测试覆盖 Tab 聚焦、方向键调整、Home/End、阈值边界和非空 `aria-live` 播报。
- 减少动态效果模式的回归测试断言：阈值闪烁、路径运动和 Remotion 连续播放被禁用，但文本状态、关键节点和因果链高亮完整保留。
- `npm run check:data`、`npm test`、`npm run lint`、`npm run build` 全部通过后才能部署。
